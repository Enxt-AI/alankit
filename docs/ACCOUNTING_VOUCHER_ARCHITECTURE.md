# 📘 Accounting & Voucher Architecture Guide (AI Agent & Developer Guide)

> **CRITICAL RULE FOR ALL AI AGENTS & DEVELOPERS**: Read this document carefully before making ANY modifications to voucher generation, ledger resolution, webhook processing, or accounting modules.

---

## 🎯 Executive Summary & Core Rules

There are **TWO DISTINCT TYPES** of Receipt Vouchers (`RECEIPT` / `RCP-`):

### 1. Order Payment Receipt Vouchers (Client Stock Purchases via Cashfree)
- **Purpose**: Recorded automatically when a user pays via Cashfree on the web/app for stock purchases.
- **Microservices Involved**: `apps/payments-service` (Cashfree Webhook Handler) & `apps/stocks-service` (Orders Service).
- **Mandatory Accounting Entries**:
  - **DEBIT (+)**: `CASHFREE PAYMENTS INDIA PVT LTD` (Cashfree Payment Gateway Control Ledger).
  - **CREDIT (-)**: `User Ledger` (e.g., `Priyatam Saxena`).
- **STRICT CONSTRAINT**: **MUST NEVER USE HDFC BANK LEDGER!** `HDFC Bank` MUST NEVER be debited for user stock payment receipts.
- **Fail-safe Guard**: `getCashfreeLedger()` must be called to resolve the ledger. Never use `findFirst({ where: { type: 'BANK', isActive: true } })` because `HDFC Bank` is the first bank ledger in PostgreSQL and will cause wrong debit entries!

### 2. Bank Settlement Receipt Vouchers (Cashfree Payouts into Company Bank Account)
- **Purpose**: Recorded automatically when Cashfree settles payout batches into the company's bank account (`BANK_SETTLEMENT`).
- **Microservice Involved**: `apps/stocks-service` (Accounting Service Reconciliation).
- **Mandatory Accounting Entries**:
  - **DEBIT (+)**: `HDFC Bank – 57500001892772` (Company Bank Ledger).
  - **CREDIT (-)**: `CASHFREE PAYMENTS INDIA PVT LTD` (Gateway Ledger clears settlement balance).
- **Metadata Marker**: Must carry `metadata: { voucherClass: "BANK_SETTLEMENT", settlementId: "..." }`.

## 🏗️ Microservice Code Locations & Guards

### 1. `apps/payments-service` (`src/payments/payment.service.ts`)
- **Webhook Handler**: `processWebhookPayload()` handles live Cashfree webhook events.
- **Voucher Generator**: `generateVouchers(order)` creates the Order Payment Receipt Voucher (`RCP-xxxx`).
- **Ledger Resolution**: Uses `getCashfreeLedger()` to fetch/auto-create `CASHFREE PAYMENTS INDIA PVT LTD`.
- **Constraint**: **NEVER** use `this.prisma.ledger.findFirst({ where: { type: 'BANK' } })` inside `generateVouchers()`!

### 2. `apps/stocks-service` (`src/orders/orders.service.ts`)
- **Voucher Generator**: `generateReceiptVoucher(order)` creates Order Receipt Vouchers.
- **Runtime Guard**: Contains an in-line fail-safe assertion:
  ```ts
  if (bankLedger.name.toUpperCase().includes('HDFC')) {
    // Intercepts and forcibly re-resolves to CASHFREE PAYMENTS INDIA PVT LTD
  }
  ```

### 3. `apps/stocks-service` (`src/accounting/accounting.service.ts`)
- **Startup Sync Task**: `fixVoucherHDFCLedgers()` (invoked in `onModuleInit()`) cleans up misplaced order receipts (`RCP-`) and payment/charge vouchers (`PAY-`, `PAYMENT`, `GATEWAY_CHARGES`) on startup by migrating them from `HDFC Bank` to `CASHFREE PAYMENTS INDIA PVT LTD`.
- **Runtime Guard**: `createVoucher()` and `updateVoucher()` automatically redirect any `HDFC Bank` entry on non-`BANK_SETTLEMENT` and non-`CONTRA` vouchers (`RECEIPT`, `PAYMENT`, `PAY-`) to `CASHFREE PAYMENTS INDIA PVT LTD`.
- **Strict Exclusion**: Explicitly preserves `metadata.voucherClass === 'BANK_SETTLEMENT'` and `metadata.voucherClass === 'CONTRA'` so that only Bank Settlement Vouchers and inter-bank Contra transfers remain on `HDFC Bank`.

## 📊 Summary Table of Voucher Types & Ledgers

| Voucher Type | Trigger Event | Debit (+) Ledger | Credit (-) Ledger | Metadata Tag |
| :--- | :--- | :--- | :--- | :--- |
| **Order Payment Receipt** (`RCP-`) | Client pays via Cashfree for stock | `CASHFREE PAYMENTS INDIA PVT LTD` | `User Ledger` (Client) | `{ autoGenerated: true, orderId: "..." }` |
| **Bank Settlement Receipt** (`RCP-`) | Cashfree settles payout to bank | `HDFC Bank – 57500001892772` | `CASHFREE PAYMENTS INDIA PVT LTD` | `{ voucherClass: "BANK_SETTLEMENT", settlementId: "..." }` |
| **Sales Voucher** (`SAL-` / `INV-`) | Share delivery confirmed | `User Ledger` (Client) | `Sale of Unlisted Share` | `{ scriptName, isin, qty, rate }` |
| **Purchase Voucher** (`PUR-`) | Company buys stock from seller | `Stock Inventory Ledger` | `Seller / DP Ledger` | `{ scriptName, isin, qty, rate }` |

## 🔒 Permanent Rule Checklist for AI Agents

1. ❌ **NEVER** run `findFirst({ where: { type: 'BANK', isActive: true } })` to get a bank ledger for order payments. Always call `getCashfreeLedger()`.
2. ❌ **NEVER** overwrite Bank Settlement Receipt Vouchers (`voucherClass === 'BANK_SETTLEMENT'`) during bulk ledger fix tasks.
3. ❌ **NEVER** put `qty`, `rate`, `isin`, or `scriptName` on `RECEIPT` (`RCP-`) voucher entries in the DB.
4. ✅ **ALWAYS** route `payments-service` webhook receipt vouchers to `CASHFREE PAYMENTS INDIA PVT LTD`.
5. ✅ **ALWAYS** run `npm run build` in both `apps/payments-service` and `apps/stocks-service` after modifying accounting logic.
